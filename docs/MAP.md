# MAP — where everything is, and how it moves

The long map of the project. `CLAUDE.md` (read first, loaded into every session) has the rules, the commands
and the traps; this page has the detail: the parts of the program, how a request and a record travel, every
feature with its files, every page, and the recipes for the usual changes. To look a single file up, use
[`FILES.md`](./FILES.md) (generated by `npm run map`: every source file with its own one-line description).

## 1. The parts, in one picture

```
                         ┌──────────────── Vercel (deploys main) ─────────────────┐
browser ─ /app ─────────▶│ /app page (bare shell) + /_next/static + /pglite + /spir│
  │  (the web app)       │ /api/cloud    one sync move on the company's database   │──▶ company DB (Postgres,
  │  PGlite in a worker  │ /api/license* codes server: activate, check, signup,    │     linked to the code)
  │  IndexedDB           │               errors, admin (owner panel /licenses)     │──▶ codes DB (Neon, or
  │  offline-sw.js cache │ server pages  the full program, rendered on the server  │     embedded)
  │                      └─────────────────────────────────────────────────────────┘
  └─ everything in the web app runs on the browser's own database; the server is
     only asked for the code (license), for sync, and for a new release.

installed computer (CLOSED — windows-archive/): the same Next.js server on 127.0.0.1:3000
  with PGlite on disk, LAN sync :3310, remote gateway :3300, auto backup, in-app updater.
```

Three faces of one code base:

| Face | Entry | Database | Status |
| --- | --- | --- | --- |
| **Web app** `/app` | `src/app/app/page.tsx` → `components/local/LocalApp.tsx` | PGlite in the browser (`idb://spir-<lid>`), synced to the company DB through `/api/cloud` | **the product now**; works offline after the first open |
| **Web site** (server-rendered) | every other `src/app/**/page.tsx`, `src/app/actions/*` | `getDb()` (PGlite on the server) or the company DB (`companyDb`) | deployed on Vercel; also the reference each web-app page copies |
| **Codes server** | `/licenses`, `/api/license/*`, `/verify/[token]` | `LICENSE_DATABASE_URL` (Neon) or embedded | on the owner's Vercel site |
| Installed version | `windows-archive/` | PGlite on disk | **closed**: not built, tested or released; kept for later |

All business rules live in SQL (`supabase/migrations/*.sql`): the same functions and triggers run in the
browser, on the server, and on the hosted database. A screen never re-implements a rule — it calls the RPC.

## 3. How things move

### 3.1 The web app opens (`/app`)

1. `src/app/app/page.tsx` renders a bare page (no license gate, `x-spir-user: shell`); `/app`, `/pglite/*`,
   `/spir/*` are public in `src/middleware.ts`.
2. `components/local/LocalApp.tsx` mounts only in the browser and calls `runtime().start()` (`lib/local/runtime.ts`,
   one per page on `window.__spirLocalRuntime`).
3. `start()`: the saved license (`lib/local/license.ts`, localStorage) → none: phase `need_code` → `Gate.tsx`
   `Activate` (code, or «try it free» → `POST /api/license/signup`). With a license: `open()`:
   - PGlite starts in a module worker (`/spir/db-worker.js`, generated), database `idb://spir-<lid>`,
     relaxed durability;
   - `migrate.ts` applies what `_spir_migrations` lacks from `/spir/migrations.json`, in one batch;
   - the license is judged offline (`lib/license/state.ts` `judge`, ES256 checked with WebCrypto);
   - first time with a company DB: phase `first_sync` (a full copy through `/api/cloud`);
   - phase `sign_in` → `SignIn` (the code itself, or a user's email + password via `fn_verify_login`),
     session in localStorage 12 h → phase `ready`.
4. The shell: hash router `route()` in `LocalApp.tsx` — `#/` main menu, `#/s/<station>`, `#/e/<entity>[/new|/<id>[/edit]]`,
   `#/sales`, `#/attendance`, `#/temperatures`, `#/guides[/<id>]`, `#/license`, `#/device`. The station chosen
   is kept in localStorage `spir.local.station`; the sidebar shows only its pages.
5. In the background (`startBackground`): sync every minute, when the connection comes back, and 4 s after a write (`afterWrite`), license check
   every few hours (`checkLicense` → `/api/license/check`), site info (`refreshSite` → `GET /api/license`).
6. `AppInstall.tsx` asks `public/offline-sw.js` to `spir-prepare`: the whole app is cached once
   (`spir-app-<hash>`), with progress; rechecked every 30 min and on `online`; a new release → «reload».

### 3.2 A web-app page reads and writes

`entity.tsx` (`EntityList` / `EntityForm` / `EntityRecord`) takes an entry of `lib/local/registry.ts` and runs
`rt.client.from(table).select(…)` — `PgRestClient` of `lib/db/rest-core.ts`, the same builder the server uses —
on the browser's PGlite. Buttons call the same RPCs as the server pages (`rt.client.rpc("fn_…")`). A write fires
the change-log triggers (`_spir_changes`) like anywhere else, so the next sync carries it.

### 3.3 Sync (every face)

- Every database logs row changes in `_spir_changes`; `lib/sync/core.ts` moves them: `syncOnce(local, peer)` =
  `pushTo` + `pullFrom`, with `snapshotFrom` on a gap and `renameOnConflict` on duplicate codes.
- The web app's peer is `cloudPeer` (`lib/cloud/serve.ts`) posting to `/api/cloud` (`src/app/api/cloud/route.ts`):
  `cloudAuth` (license token + seat, `lib/cloud/auth.ts`) → `companyDb(url)` (`lib/db/pglite.ts`) → `serveCloud`
  (`hello/pull/push/meta/snap`). The database's connection string never leaves the server.
- The server's own peer choice (hosted DB / main computer over LAN) is `lib/sync/engine.ts`; LAN transport
  `lib/sync/lan.ts`. Details and rules: CLAUDE.md «Sync model».

### 3.4 A code (license)

- The owner makes a code on `/licenses` (`components/licenses/*`, `/api/license/admin`, rules in
  `lib/license/core.ts`, runner `lib/license/server.ts`).
- A browser activates it: `POST /api/license/activate` → a signed license (ES256) with the stations
  (`lib/license/modules.ts`), seats, end date, max offline days, the company DB link (sealed), `verify_key`.
- It is re-checked with `POST /api/license/check` (renewals, stops, messages, the device's sync report);
  judged offline in between by `lib/license/state.ts` `judge`.
- The web app reports its errors to `POST /api/license/errors` when the owner turned the error log on.
- Self-registration: `POST /api/license/signup` gives a trial code when the owner allowed it.

### 3.5 A server page (web site)

`src/middleware.ts` (cookie signature, public paths, welcome redirect) → `src/app/layout.tsx` (session still
valid, license gate, bell notices) → `page.tsx` → `createClient()` (`lib/supabase/server.ts`) → `rest.ts`
(access guard per query) → `getDb()`. Forms post to server actions in `src/app/actions/*`, which return
`{ error }` or redirect with `?done=…`.

## 4. Recipes

| To … | Do |
| --- | --- |
| add a page to the web app | add an entry to `ENTITIES` in `lib/local/registry.ts` (table, list select/columns/search, fields, lines, actions); `tests/local-registry.test.mjs` checks it against the real schema. A page that is not a list/form goes in `route()` of `LocalApp.tsx` + a screen in `components/local/` |
| add a table or a business rule | a new migration `supabase/migrations/NNNN_name.sql` (rules in CLAUDE.md «Database»), then `npm run schema`; the web app gets it through `prepare-local-app.mjs` automatically |
| add a visible string | `t(locale, "English key")` + the Arabic value in `lib/i18n.ts`; a stored choice value goes in `tValue` |
| add a station | `lib/license/modules.ts` (id, label, nav `groups`, `tone`) + the nav group in `lib/nav.ts` + registry entries with that `station` (and `SPECIAL_PAGES` in `registry.ts` for non-list pages) |
| add a section to the owner's panel | `src/app/licenses/page.tsx` + a component in `components/licenses/` + an op in `/api/license/admin`; `tests/browser/e2e-license.mjs` counts the sections |
| add a file the web app needs offline | it must be named by `/app` or listed in `local.json` `files` (`scripts/prepare-local-app.mjs`) |
| add, move or remove a source file | `npm run map` (rewrites `docs/FILES.md`; `tests/map.test.mjs` fails otherwise) |
| release | open a PR; CI green → squash-merge; Vercel deploys `main`; open web apps download it in the background |
| reopen the Windows version | `windows-archive/README.md` «إعادة فتحها» |
